## 🧩 Завдання 1: Алгоритмічний розігрів (Custom Unwind Utility)

### Мета

Відтворити логіку поведінки оператора MongoDB `$unwind` на TypeScript за допомогою Generics та функціонального програмування.

### Вхідні дані

```typescript
export type OrderWithItems = {
  orderId: string;
  customerId: string;
  createdAt: string;
  items: Array<{
    productId: string;
    quantity: number;
    price: number;
  }>;
};

export const sampleOrders: OrderWithItems[] = [
  {
    orderId: "ord-101",
    customerId: "cust-1",
    createdAt: "2026-03-01",
    items: [
      { productId: "prod-A", quantity: 2, price: 100 },
      { productId: "prod-B", quantity: 1, price: 250 },
    ],
  },
  {
    orderId: "ord-102",
    customerId: "cust-2",
    createdAt: "2026-03-02",
    items: [{ productId: "prod-C", quantity: 5, price: 30 }],
  },
  {
    orderId: "ord-103",
    customerId: "cust-3",
    createdAt: "2026-03-03",
    items: [], // Порожній масив!
  },
];
```

### Вимоги до реалізації

1. **Generic-сигнатура:**
   Напиши універсальну функцію `unwind`:

   ```typescript
   export type UnwoundDocument<T, K extends keyof T> = Omit<T, K> & {
     [P in K]: T[K] extends Array<infer Item> ? Item : never;
   };

   export function unwind<T extends Record<string, any>, K extends keyof T>(
     docs: T[],
     arrayKey: K,
     options?: { preserveNullAndEmptyArrays?: boolean },
   ): Array<UnwoundDocument<T, K> | (Omit<T, K> & { [P in K]?: null })>;
   ```

2. **Логіка роботи:**
   - Для кожного елемента вкладеного масиву створюється окрема копія батьківського об'єкта, де поле `arrayKey` містить уже не масив, а один його конкретний елемент.
   - Опція `preserveNullAndEmptyArrays`:
     - Якщо `false` (за замовчуванням): документи з порожнім масивом, `null` або `undefined` ігноруються і не потрапляють у фінальний результат.
     - Якщо `true`: такий документ повертається, а цільове поле встановлюється в `null`.
   - Забезпечити чисту роботу без мутації оригінальних об'єктів.

## 🔗 Завдання 2: Реляційні джоїни у NoSQL ($lookup та $unwind)

### Мета

Збагатити аналітичні дані замовлень інформацією про клієнтів та характеристиками придбаних товарів за допомогою оператора `$lookup`.

### Кроки реалізації

1. **Створення зв'язаних колекцій у MongoDB:**
   - Додай у схеми Mongoose дві додаткові сутності:
     - `Customer`: `_id`, `name`, `email`, `tier` (`'BRONZE' | 'SILVER' | 'GOLD'`).
     - `Product`: `_id`, `sku`, `title`, `costPrice` (собівартість для розрахунку маржі).
   - Наповни колекції тестовими записами через скрипт `seed`.

2. **Простий $lookup (Equality Match):**
   - У `AnalyticsService` реалізуй метод `getOrderDetailsWithCustomer(orderId: string)`:

     ```typescript
     {
       $lookup: {
         from: 'customers',
         localField: 'customerId',
         foreignField: '_id',
         as: 'customer'
       }
     }
     ```

   - Оскільки `$lookup` завжди повертає масив, застосуй `$unwind` для поля `$customer` з опцією `preserveNullAndEmptyArrays: true` (щоб не втратити замовлення, якщо клієнта видалено).

3. **Корельований $lookup із вкладеним конвеєром (Correlated Subquery):**
   - Реалізуй вибірку топових замовлень із розрахунком чистого прибутку (Margin = `totalPrice - costPrice`):
     - Використай форму `$lookup` з параметрами `let` та `pipeline` для приєднання списку товарів за умовами:

     ```typescript
     {
       $lookup: {
         from: 'products',
         let: { itemIds: '$items.productId' },
         pipeline: [
           { $match: { $expr: { $in: ['$_id', '$$itemIds'] } } },
           { $project: { title: 1, costPrice: 1 } }
         ],
         as: 'productDetails'
       }
     }
     ```

   - Розрахуй сумарну собівартість та маржинальність кожного замовлення.

## 📊 Завдання 3: Фасетні звіти ($facet) та цінові сегменти ($bucket)

### Мета

Згенерувати комплексний бізнес-дашборд для керівництва за **один запит до бази даних**, уникаючи виконання 3-4 окремих важких звернень.

### Кроки реалізації

1. **Реалізація аналітичного ендпоінта в `AnalyticsService`:**
   Створи метод `getExecutiveDashboard(startDate: Date, endDate: Date)`.
2. **Конвеєр із $facet:**
   Конвеєр повинен починатися з попередньої фільтрації `$match` (за статусом `COMPLETED` та періодом), після чого спрямовуватися в оператор `$facet`:
   - **Фасет 1 (`summary`):**
     - Підрахунок загального доходу (`totalRevenue`), середнього чека (`avgOrderValue`), загальної кількості замовлень (`totalOrders`).
   - **Фасет 2 (`topProducts`):**
     - Розгортання масиву куплених товарів через `$unwind: '$items'`.
     - Групування за `items.productId`, підрахунок проданих штук та виручки.
     - Сортування за спаданням виручки та взяття перших 5 (`$limit: 5`).
   - **Фасет 3 (`categoryBreakdown`):**
     - Групування за категорією товару з підрахунком частки кожного сегмента.
   - **Фасет 4 (`priceTiers`):**
     - Сегментація замовлень за вартістю за допомогою оператора `$bucket`:
       - Межі (`boundaries`): `[0, 100, 500, 1000, 5000]`.
       - `default`: `'VIP (5000+)'`.
       - Підрахунок кількості замовлень та суми виручки в кожному діапазоні.
3. **Обробка та типізація вихідного результату:**
   Створи інтерфейс `ExecutiveDashboardResponseDto` та поверни зібрані дані через контролер.

## 🎯 Питання для самоперевірки та інтерв'ю

1. **Оптимізація `$lookup`:** Чому відсутність індексу на полі `foreignField` у приєднуваній колекції здатна перетворити запит на катастрофу за продуктивністю ($O(N \times M)$)?
2. **Вибух декартового добутку при `$unwind`:** Чим небезпечне виконання `$unwind` для масивів великої довжини (наприклад, сотні елементів) перед важкими стадіями групування?
3. **Обмеження пам'яті в `$facet`:** Чи підтримує оператор `$facet` параметр `allowDiskUse: true` для запису тимчасових даних на диск у версіях MongoDB і які обмеження на розмір фінального BSON-документа тут діють?
4. **Embedding vs Referencing:** Чому в MongoDB часто віддають перевагу денормалізації (зберіганню імені клієнта прямо всередині замовлення), ніж постійному використанню `$lookup`?
